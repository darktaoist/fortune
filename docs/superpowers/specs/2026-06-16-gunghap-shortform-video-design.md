# 궁합 결과 숏폼 영상 자동 생성 — 설계 문서

날짜: 2026-06-16
상태: 설계 확정 대기(사용자 리뷰)

## 1. 개요 & 목표

연예인 궁합 결과를 **세로형(9:16) 모션그래픽 숏폼 MP4(약 20초)** 로 자동 생성해, 사용자가 틱톡/릴스/쇼츠에 공유하게 한다. 목적은 매출 직결이 아니라 **트래픽 유입 루프**(공유 영상 → 사이트 방문 → 무료/유료 전환)다.

핵심 원칙: **건당 비용 0 · 서버 부하 0 · 무한 확장.** 1GB VPS를 전혀 건드리지 않기 위해 렌더링을 전부 **사용자 브라우저**에서 수행한다.

## 2. 범위

### 포함 (v1)
- 연예인 궁합 결과 한정. 결과 페이지에 "영상으로 공유" 버튼 추가.
- 브라우저 클라이언트 렌더링 → MP4 다운로드 + 모바일 Web Share.
- 다크+골드 브랜드 톤, 배경음악(로열티프리), 워터마크(로고+URL).
- 연예인 사진은 **일러스트/포스터화 필터** 적용(법적 완충).

### 제외 (후속)
- 평생운세·신년운세 등 다른 상품의 결과 숏폼(템플릿 일반화는 염두에 두되 v1엔 미구현).
- AI 이미지→비디오(사진이 실제로 움직이는) 방식.
- 서버사이드/외부 렌더링.

## 3. 사용자 플로우

1. 사용자가 연예인 궁합 결과를 본다(기존 결과 화면).
2. "영상으로 공유" 버튼 클릭 → 렌더 모달 오픈.
3. 진행바와 함께 브라우저에서 20초 영상 인코딩(약 5~20초 소요).
4. 완료 → 미리보기 + [다운로드] / 모바일은 [공유](Web Share API로 틱톡·IG 등 직접 전달).
5. (선택) 미지원 브라우저는 폴백(아래 7.4).

만들 사람만 만들도록 **버튼 트리거**로 한다(결과마다 자동 렌더 아님 → 낭비 0).

## 4. 콘텐츠 & 스토리보드 (9:16, 1080×1920, 30fps, ~20s)

20초 안에 8섹션 전부가 아니라 **핵심만 압축**한다.

| 구간 | 내용 |
|---|---|
| 0–3s | 훅: "○○ ♥ [연예인]" 두 얼굴 슬라이드인 + "우리 궁합은…?" 서스펜스 |
| 3–7s | 리빌: 큰 궁합 점수(예 87) 팝 + 파티클 버스트 + 연예인 사진 줌 |
| 7–16s | 요약: 한줄평 + 키포인트 2~3개 텍스트 애니메이션, 사진 켄번스 팬/줌 |
| 16–20s | CTA: "내 궁합도 확인 → taoist.co.kr" + 로고 + QR + 띠 글리프 |

하단에는 전체 구간 내내 **로고 + `taoist.co.kr`** 워터마크 상시 노출.

### 데이터 입력 (추가 AI 비용 없음)
기존 궁합 결과 데이터를 재사용한다:
- 본인 표시명, 연예인 이름/슬러그(→ `public/celebs/` 이미지 경로).
- 궁합 점수(있으면), 한줄평, 섹션 요약에서 추출한 짧은 문장 2~3개.
- 별도 LLM 호출 없이 기존 결과 텍스트에서 추려 매핑(`buildVideoStoryboard(result)` 순수 함수).

## 5. 기술 아키텍처 (전부 클라이언트)

### 5.1 모듈 구성
- `composables/useShortform.ts` — 오케스트레이션(데이터→스토리보드→렌더→인코딩→출력).
- `utils/shortform/storyboard.ts` — 결과 데이터 → 키프레임 타임라인(순수 함수, 테스트 가능).
- `utils/shortform/renderer.ts` — 프레임별 Canvas 2D 합성(배경·사진·텍스트·파티클·워터마크).
- `utils/shortform/illustrate.ts` — 사진 포스터화/듀오톤 필터(Canvas 픽셀 처리).
- `utils/shortform/encode.ts` — WebCodecs(VideoEncoder/AudioEncoder) + `mp4-muxer`로 MP4 muxing, 폴백 포함.
- `components/ShareVideoModal.vue` — 버튼/진행바/미리보기/다운로드·공유 UI.

각 모듈은 단일 책임 + 명확한 입출력 인터페이스로 독립 테스트 가능하게 둔다.

### 5.2 렌더 & 인코딩
- Canvas 2D로 30fps × 20s = **600 프레임**을 결정적(deterministic)으로 그린다(실시간 RAF 아님, 프레임 인덱스 기반).
- 각 프레임을 `VideoEncoder`(H.264/avc1)로 인코딩, 배경음악은 Web Audio로 디코딩 후 `AudioEncoder`(AAC)로 인코딩.
- `mp4-muxer`로 비디오+오디오 트랙을 MP4 컨테이너로 합성 → Blob.
- 해상도 1080×1920, 비트레이트는 모바일 공유 적정선(약 6~8Mbps)로 설정.
- 가능하면 OffscreenCanvas + Web Worker로 메인스레드 블로킹 최소화(v1은 메인스레드 허용, 진행바로 UX 보완).

### 5.3 일러스트 필터 (법적 완충 a안)
연예인 사진에 Canvas 픽셀 처리로 **색 단계 축소(posterize) + 골드 듀오톤 + 약한 외곽선** 을 적용해 "공식 사진" 느낌을 줄인다. 결정적 처리(서버/외부 호출 없음). 단, 이는 리스크 **완화**지 제거가 아님(아래 9).

### 5.4 폴백 (서버 부하 0 유지)
- WebCodecs 미지원: `canvas.captureStream()` + `MediaRecorder`로 **WebM** 생성.
- 둘 다 불가: Canvas → **정지 이미지 카드(PNG)** 로 폴백(항상 무언가는 손에 쥐게).
- 어떤 경우에도 서버 렌더로 넘기지 않는다.

### 5.5 배포/공유
- 모바일: `navigator.share({ files: [mp4] })` 지원 시 직접 공유.
- 미지원/데스크톱: 다운로드 버튼.

## 6. 음악
로열티프리(저작권 안전) 트랙 1~2개를 `public/shortform/audio/`에 번들. 출처는 라이선스 명확한 것(CC0 또는 구매)으로 한정하고 라이선스 근거를 리포지토리에 기록. 트랙 길이는 ≥20s, 루프/페이드아웃 처리.

## 7. 에러 처리 & 성능
- 인코딩 실패 시 폴백 체인(WebCodecs→MediaRecorder→PNG)으로 자동 강등, 사용자에게 상태 안내.
- 연예인 이미지 로드 실패 시 글리프/실루엣 플레이스홀더로 대체(렌더 중단 금지).
- 진행바로 600프레임 진행률 표시, 취소 버튼 제공.
- 저사양 기기 대비: 해상도/비트레이트는 상수로 관리해 추후 조정 가능.

## 8. 테스트
- 단위: `storyboard.ts`(데이터→타임라인 매핑), `illustrate.ts`(필터 결정성).
- 통합: 짧은 길이(예 2s)로 인코딩 파이프라인 스모크 테스트.
- 수동: Chrome/Safari(iOS 17+)/Android Chrome 크로스브라우저, Web Share 동작.

## 9. 법적 리스크 (명시)
실명 아이돌 사진을 가공해 대량 배포하는 것은 초상권/퍼블리시티권 측면에서 **잔존 리스크**가 있다. 일러스트 필터(5.3)와 "팬 엔터테인먼트" 성격은 완화책일 뿐 면책이 아니다. 트래픽이 커지면 기획사 대응 가능성을 운영상 계속 모니터링한다. (제품 결정이며 본 설계의 기술 범위 밖.)

## 10. 향후 확장
- 다른 상품(평생/신년) 결과 요약 숏폼으로 템플릿 일반화.
- 인기 연예인 소수에 한해 AI 모션(이미지→비디오) 캐싱 하이브리드.
- A/B용 템플릿/음악 변형.

### 점수 처리(확인 완료)
궁합 결과 API는 `score` 필드를 반환한다(`server/api/fortune/premium.post.ts:76` — `result.score`가 숫자면 값, 아니면 `null`). 따라서 스토리보드는 **점수 있으면 3–7s 리빌을 점수 중심으로, 없으면(null) 한줄평 중심**으로 분기한다. 두 경로 모두 v1에서 지원.

## 11. 미해결/확인 필요
- 배경음악 구체 트랙 선정(라이선스 출처 확정) — 구현 시 1~2개 픽스.
- QR은 v1 기본 포함(경량 클라이언트 QR 생성 라이브러리 사용).
